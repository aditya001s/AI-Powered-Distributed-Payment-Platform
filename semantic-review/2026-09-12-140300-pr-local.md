# AegisPay Phase 10 deployment and release platform

Phase 10 introduces a twelve-workload Helm release, optional data and observability planes, and GitHub Actions for validation, image publication, scanning, SBOMs, and deployment. The default manifests are schema-valid, but auth-service cannot start because its inbound OAuth client secret is not injected. The production deployment and release chain also leave environment configuration, source/image alignment, and security gating unenforced. **Watch for:** **BLOCKER — confirmed:** auth-service receives no `INTERNAL_CLIENT_SECRET`; **HIGH — confirmed:** production dispatch deploys development defaults; **HIGH — confirmed:** deploy inputs permit shell injection after kubeconfig installation; **HIGH — confirmed:** publication ignores Security and CodeQL results; **HIGH — confirmed:** the frontend artifact cannot satisfy its per-environment URL contract; **HIGH — confirmed:** external data-plane security settings are unavailable; **HIGH — confirmed:** all databases share one owner credential.

**Verdict**: NEEDS_CHANGES

## High-level view

Auth-service is excluded from secret injection because it makes no outbound authenticated calls, but it needs the same secret to seed the inbound OAuth client. Its validated configuration therefore blocks the default release before readiness (**BLOCKER — confirmed**).

Deployment uses the current default-branch chart with an independently selected image tag and no target-specific values. Production consequently inherits the bundled single-node data plane, disabled Ingress, example URLs, and potentially a different configuration contract from the selected binaries (**HIGH — confirmed**).

Release controls do not form a closed chain: publication waits only for CI, deployment accepts mutable tag coordinates, and dispatch inputs are interpolated into a shell after kubeconfig installation. The frontend compounds this by baking one gateway URL into an artifact promoted to three environments (**HIGH/MEDIUM — confirmed**).

External data-plane values name endpoints but cannot provide managed-service TLS/SASL material; comma-separated Kafka addresses break init waits. The bundled plane also gives every database workload the same owner identity (**HIGH/MEDIUM — confirmed**).

Monitoring pods are outside NetworkPolicy coverage, Kafka is absent from readiness, Secret rotation does not roll consumers, and hosted AI credentials have no injection path. The project status still reports Phase 9 (**MEDIUM/LOW — confirmed**).

<details><summary>Details</summary>

## Auth client seeding is disconnected from `serviceAuth`

**BLOCKER — confirmed.** `values.yaml` marks auth-service `serviceAuth: false`, and `applications.yaml` injects `INTERNAL_CLIENT_SECRET` only when that flag is true (`values.yaml:59-68`; `templates/applications.yaml:107-110`). Auth-service also needs the secret for the inbound client-credentials client (`auth-service/src/main/resources/application.yml:103-110`), whose bound `clientSecret` is `@NotBlank` (`AuthProperties.java:335-359`). The default installation cannot start auth-service despite the key existing in `secrets.template.yaml:10`; separate inbound client seeding from outbound token acquisition.

## Environment selection does not select deployment values

**HIGH — confirmed.** The Helm command overrides only registry, namespace, tag, and runtime Secret (`deploy.yml:64-72`). Production therefore retains bundled PostgreSQL/Redis/single-node Kafka, enabled bundled monitoring, disabled Ingress, and example gateway/JWT URLs (`values.yaml:2-14, 208-255`), contrary to the managed-service requirement in `infrastructure/kubernetes/README.md:12`. Pass reviewed environment values and fail production deployment when development defaults remain.

## Chart and application revisions can drift

**HIGH — confirmed.** Checkout has no `ref`, so deployment uses the current default branch while `image_tag` independently selects binaries (`deploy.yml:12-14, 43-45, 68-70`). Rollback or promotion can combine old applications with new ConfigMap variables, probes, and Secret contracts. Checkout the selected commit or publish a release manifest binding chart and image digests.

## Dispatch inputs execute inside the kubeconfig-bearing shell

**HIGH — confirmed.** Free-form `image_registry`, `image_namespace`, and `image_tag` values are inserted directly into a multiline shell script (`deploy.yml:12-25, 64-72`). Quotes and shell metacharacters can execute commands after the kubeconfig is decoded (`deploy.yml:46-55`). Pass inputs through step `env` and validate registry, namespace, and SHA/digest formats.

## Security analysis is not a publication gate

**HIGH — confirmed.** `images.yml:4-23` listens only for the `CI` workflow and does not wait for `Security` or `CodeQL`. Images can publish for a SHA whose secret, dependency/source, infrastructure, or static analysis failed. Trigger publication only after one same-SHA gate verifies all required workflows.

## Tag references and SBOMs do not establish release immutability

**MEDIUM — confirmed.** The chart deploys `registry/namespace/service:tag` (`_helpers.tpl:38-43`), and deploy accepts arbitrary coordinates without verifying publication (`deploy.yml:12-25, 68-70`). Tags remain mutable, while SBOMs are retained as separate workflow artifacts (`images.yml:76-88`). Deploy digests and attach SBOM/provenance attestations to those digests.

## One frontend build cannot be promoted across three targets

**HIGH — confirmed.** Frontend is built once with one `vars.PUBLIC_GATEWAY_URL` (`images.yml:41`) and the same tag can target development, staging, or production (`deploy.yml:6-14`). The URL is embedded into the Vite bundle and CSP (`Dockerfile.frontend:56-62, 84-90`), while `infrastructure/kubernetes/README.md:26` requires a rebuild per environment. Publish environment-qualified frontend coordinates or introduce safe runtime configuration without overwriting a SHA tag with different bytes.

## External mode cannot express secure managed-service connections

**HIGH — confirmed.** External PostgreSQL/Redis expose host/port and shared credentials; Kafka exposes only `bootstrapServers` (`values.yaml:208-233`; `configmap.yaml:16-41`). There is no database SSL/CA/client-certificate, Redis TLS, Kafka security protocol/SASL/trust material, or constrained extra env/volume surface in `applications.yaml`. Add Secret-backed TLS/auth values and validate them whenever bundled components are disabled.

## Multi-broker Kafka addresses strand workloads in init

**MEDIUM — confirmed.** The wait command treats all of `bootstrapServers` as one `host:port` (`applications.yaml:64-69`). For `broker1:9092,broker2:9092`, it computes host `broker1:9092,broker2`, leaving all Kafka-dependent deployments in init until Helm times out. Parse individual entries safely or remove the ad-hoc wait.

## Database-per-service uses one owner for all databases

**HIGH — confirmed.** Bundled PostgreSQL creates every database as one `POSTGRES_USER` (`data-plane.yaml:1-34, 89-94`); all workloads receive that user and one password (`configmap.yaml:21-31`; `applications.yaml:97-100`; `secrets.template.yaml:9`). Compromise of any database-connected service grants access across all service databases. Create distinct logins, grants, and Secret keys per database, including external mode.

## Internal OAuth calls share one identity

**MEDIUM — confirmed.** One global `aegis-internal` client ID and `INTERNAL_CLIENT_SECRET` are distributed to every `serviceAuth` workload (`values.yaml:194-206`; `applications.yaml:107-110`), and auth seeds one shared client (`auth-service/src/main/resources/application.yml:103-114`). A leaked credential impersonates every caller and audit records cannot attribute the workload. Issue per-service client identities and least-privilege scopes.

## Hosted AI configuration has no Secret path

**MEDIUM — confirmed.** The chart exports provider, model, and base URL (`values.yaml:196-202`; `configmap.yaml:56-61`) but no `AI_API_KEY`; the AI service reads that variable and otherwise falls back locally (`ai-investigation-service/src/main/resources/application.yml:136-143`). Add a Secret-backed key only when a hosted provider is selected.

## Secret rotation does not roll consumers

**MEDIUM — confirmed.** Application templates checksum only the ConfigMap (`applications.yaml:24-26`), and monitoring templates checksum only monitoring configuration (`monitoring.yaml:65-67, 133-135, 186-188, 251-253`). Secret-backed environment values do not update in running processes, and auth loads signing material at startup. Add a reloader, Secret-version annotation, or mandatory rollout procedure.

## Monitoring endpoints lack ingress isolation

**MEDIUM — confirmed.** NetworkPolicies cover twelve applications and three data-plane names only (`access.yaml:58-113`); Prometheus, Tempo, OTel Collector, and Grafana have none. Without a cluster-level default deny, other namespaces can reach their ClusterIP APIs, including unauthenticated Prometheus and Tempo endpoints. Add monitoring-specific allowlists and an explicit ingress-controller namespace selector.

## Kafka outages are invisible to JVM readiness

**MEDIUM — confirmed.** Kafka is checked only by init containers (`applications.yaml:64-69`), while shared readiness includes only `readinessState`, `db`, and `redis` (`platform-common/src/main/resources/aegis-defaults.yml:188-196`). A post-start broker outage leaves Kafka-dependent pods ready while durable event processing is unavailable. Add a bounded Kafka health contributor or document and alert the deliberate fail-open behavior.

## Phase status contradicts the implementation section

**LOW — confirmed.** `README.md:20` still reports Phase 9 and `README.md:2979` leaves Phase 10 unchecked despite the implementation section at `README.md:2912`. Update both after blocking and high findings are resolved.
