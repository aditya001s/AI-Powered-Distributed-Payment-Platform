# Phase 1–10 remediation leaves ambiguous payment effects unsafe

The remediation strengthens row locking, durable wallet idempotency, post-handler event marking, deployment isolation, RAG provenance, reconciliation, and operational tooling. Three failure paths can still strand or misstate financial effects, and the citation migration can block upgrades containing hallucination evidence. Production chart assertions also allow insecure dependency transport and unsafe runtime switches, while recovery accounting reports a deferred retry as recovered. **Watch for:** **HIGH — confirmed:** an unconfirmed provider orphan can be followed by authorization at another provider; **HIGH — confirmed:** failure to record an ambiguous ledger/capture outcome can fall into stale-state compensation; **HIGH — confirmed:** V6 backfill is rejected by the V3 append-only trigger; **MEDIUM — confirmed:** deferred sagas are counted as recovered; **MEDIUM — confirmed:** the production profile accepts plaintext dependency transport and unsafe application switches.

**Verdict**: NEEDS_CHANGES

## High-level view

If provider authorization lookup or void cannot be confirmed after a timeout, the code only logs the unresolved charge and continues to the next provider. One payment can acquire two provider authorizations while the saga retains only the second handle (**HIGH — confirmed**).

Ledger and wallet capture timeouts are classified as `RecoveryRequired`, but the diagnostic `stepFailed` write happens before that classification is thrown. An orchestrator-database failure can replace `RecoveryRequired` with a generic exception and invoke compensation from stale saga state (**HIGH — confirmed**).

Upgrades containing a hallucinated citation fail because V6 updates the append-only citation table while the V3 `BEFORE UPDATE` trigger remains enabled (**HIGH — confirmed**).

The recovery sweep cannot tell that `advance` swallowed `RecoveryRequired`; it increments the recovered metric and return count despite leaving the saga at the same step (**MEDIUM — confirmed**).

The production Helm profile checks topology and release identity, but not dependency transport security or risky application flags. A production render can pass with plaintext PostgreSQL, Redis, or Kafka, demo seeding enabled, or unassessed payments allowed (**MEDIUM — confirmed**).

The exact combined failure cases behind the three HIGH findings have no automated coverage, so fresh-database and successful-cleanup tests cannot detect them (**MEDIUM — confirmed**).

## Provider fallback can authorize the same payment twice

**HIGH — confirmed.** `payment-orchestrator/src/main/java/com/aegispay/orchestrator/service/SagaOrchestrator.java:645-660` catches every `ProviderFaultException`, attempts orphan cleanup, and then resumes the candidate loop. `releaseOrphanedAuthorization` returns normally both when `gateway.voidQuietly` reports failure (`:702-711`) and when lookup itself throws (`:713-717`). A timed-out authorization can remain live at provider A while provider B approves; only provider B's authorization is persisted, so ordinary compensation has no handle for provider A.

Make orphan reconciliation a gate. Return a typed result such as `NO_AUTHORIZATION`, `VOIDED`, or `UNRESOLVED`, and allow fallback only for the first two. Persist the unresolved provider/idempotency reference and stop with a recovery-required state; recovery must reconcile that same provider before routing can choose another.

## Ambiguous ledger and capture outcomes can lose fail-forward handling

**HIGH — confirmed.** The timeout branches at `SagaOrchestrator.java:729-733` and `:759-763` call `mutations.stepFailed` before throwing `RecoveryRequired`; completion repeats the pattern at `:793-798`. If that diagnostic write throws, `advance` never sees `RecoveryRequired` and its generic exception branch at `:257-266` calls `settle` using stale status. For an ambiguous capture, compensation can reverse the ledger even though wallet capture moved funds. For an ambiguous ledger call, it can release the hold while an untracked posting remains.

Diagnostic persistence must not change the safety classification. Wrap `stepFailed` in a best-effort helper and unconditionally throw the original `RecoveryRequired`, or atomically persist a dedicated recovery state without depending on the downstream outcome. Apply the same rule to provider ambiguity and completion.

## V6 cannot backfill historical hallucinations through the append-only table

**HIGH — confirmed.** V3 creates `trg_investigation_citations_append_only` as a `BEFORE UPDATE OR DELETE` trigger in `ai-investigation-service/src/main/resources/db/migration/V3__investigations.sql:336-339`. V6 executes `UPDATE investigation_citations SET cited_in_report = TRUE WHERE hallucinated = TRUE` at `V6__distinguish_retrieved_and_cited_policy.sql:8-10`. Any upgraded database with a historical hallucinated citation invokes `refuse_investigation_mutation()` and aborts Flyway startup.

Drop or temporarily disable only `trg_investigation_citations_append_only` inside V6, perform the backfill, and recreate/enable it in the same transactional migration.

## Recovery metrics report deferred work as completed

**MEDIUM — confirmed.** `SagaOrchestrator.advance` catches and logs `RecoveryRequired` at `SagaOrchestrator.java:250-256` without returning an outcome or rethrowing. `SagaRecoveryService.sweep` therefore increments `aegis.saga.recovered` and its recovered count at `SagaRecoveryService.java:125-132`, while the saga remains unchanged until a later sweep.

Return an explicit `COMPLETED`, `PARKED`, or `RETRY_REQUIRED` result from resume/advance, or use a recovery-only signal that does not fail the original Kafka delivery. Count recovery only after persisted progress or terminal completion and emit a deferred-retry metric otherwise.

## Production profile permits insecure dependency transport and unsafe switches

**MEDIUM — confirmed.** `infrastructure/kubernetes/aegispay/templates/_helpers.tpl:50-67` validates managed topology, ingress, non-example endpoints, image namespace, and a 40-character tag. It does not reject `infrastructure.postgresql.sslMode=disable`, `infrastructure.redis.sslEnabled=false`, or `infrastructure.kafka.securityProtocol=PLAINTEXT`; it also permits `applicationConfig.allowUnassessedPayments=true` and `applicationConfig.demoSeedEnabled=true` in production.

Require a validating PostgreSQL SSL mode and root certificate, Redis TLS, `SASL_SSL` Kafka with required authentication/trust material, unassessed payments disabled, and demo seeding disabled.

## Missing combined-failure validation

**MEDIUM — confirmed.** Existing tests cover successful provider orphan cleanup, individual state-persistence failures after confirmed reserve/ledger/capture calls, and fresh-schema citation behavior. Not tested: provider lookup or void failure before fallback; a downstream timeout after commit combined with `stepFailed` throwing; and a V5-to-V6 migration containing grounded and hallucinated rows. Add those tests before final validation, including assertions that no later provider or compensation is called and that the citation trigger is restored after migration.
